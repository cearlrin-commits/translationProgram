# PDF 영→한 번역기

영어 PDF를 넣으면 **왼쪽에는 영어 원본, 오른쪽에는 한국어 번역본**을 나란히 놓은 PDF를 만듭니다.
번역본은 원본과 같은 위치, 글자 크기, 색, 정렬로 배치됩니다. 이미지, 도형, 배경색은 그대로 남습니다.

결과 예시는 [`examples/sample_ko_side_by_side.pdf`](examples/sample_ko_side_by_side.pdf)에서 볼 수 있습니다.

## 설치

```bash
pip install -r requirements.txt
```

한국어 글꼴은 **나눔고딕(NanumGothic)** 을 씁니다. SIL Open Font License 1.1이라 무료로 쓰고 배포할 수 있습니다.
글꼴 파일은 `pdf_translator/fonts/`에 함께 들어 있고, 라이선스는 `pdf_translator/fonts/OFL.txt`에 있습니다.
나눔고딕에 없는 글자(α, β, ① 등)는 PyMuPDF에 내장된 Droid Sans Fallback(Apache 2.0)으로 그립니다.

## 사용법

```bash
# Claude API로 번역 (ANTHROPIC_API_KEY 환경 변수 필요)
python -m pdf_translator 논문.pdf -o 논문_ko.pdf --report 보고서.json

# 무료 Google 번역 (API 키 필요 없음)
python -m pdf_translator 논문.pdf --engine google

# 직접 준비한 번역 사전 사용: {"영어 문장": "한국어 문장"} 형식의 JSON
python -m pdf_translator examples/sample_en.pdf --engine dict --dict examples/sample_translations_ko.json
```

| 옵션 | 설명 |
|---|---|
| `-o` | 좌우 비교 PDF 경로 (기본값: `입력이름_ko.pdf`) |
| `--engine` | `claude`(기본값), `google`, `dict` |
| `--pages 1-3,5` | 일부 쪽만 번역 |
| `--translated-only 경로` | 번역본만 담은 PDF도 저장 |
| `--report 경로` | 문단별 번역 검사 결과, 배치 수정 내역, 남은 차이를 JSON으로 저장 |
| `--max-fix-iterations` | 배치 검증·수정을 반복할 최대 횟수 (기본값 6) |
| `--no-header` | 위쪽의 "원본 / 번역본" 머리글 빼기 |
| `-v` | 진행 상황 출력 |

파이썬 코드에서 바로 쓸 수도 있습니다.

```python
from pdf_translator import translate_pdf, ClaudeTranslator
report = translate_pdf("in.pdf", "out.pdf", ClaudeTranslator())
print(report.ok)
```

## 동작 방식

```
PDF ─▶ ① 텍스트 인식 ─▶ ② 번역 + 문단/문장 검사 ─▶ ③ 배치 ─▶ ④ 배치 검증 ⇄ 수정 ─▶ ⑤ 좌우 합치기
```

1. **텍스트 인식** (`extract.py`): PyMuPDF로 글자마다 위치, 크기, 글꼴, 굵기, 색을 읽습니다.
   줄을 문단으로 묶고(글자 크기·굵기 변화나 넓은 줄 간격이 나오면 새 문단), 정렬 방식(왼쪽/가운데/오른쪽/양쪽),
   줄 간격, 첫 줄 들여쓰기를 알아냅니다. 줄 끝 하이픈으로 끊긴 단어는 다시 잇고, 문단을 문장으로 나눕니다
   (`segment.py`: Dr., e.g., Fig., 3.5, J. Smith, "1." 같은 번호를 문장 끝으로 착각하지 않음).
2. **번역** (`translate.py`): 문단 단위로 묶어 번역하되 영어 문장 하나에 한국어 문장 하나가 대응하도록 요청합니다.
   같은 쪽의 전체 글을 문맥으로 함께 보냅니다. 그다음 두 단계로 검사합니다(`checks.py`).
   - **문단 단위 검사**: 문장 수가 같은지, 숫자가 빠지지 않았는지, 같은 번역이 연달아 나오지 않는지(문장 정렬 어긋남), 길이 비율이 정상인지
     → 문장 수가 어긋나면 문단을 다시 번역하고, 그래도 안 되면 문장마다 따로 번역합니다.
   - **문장 단위 검사**: 비어 있지 않은지, 한글로 번역됐는지, 영어가 지나치게 남지 않았는지, 숫자가 그대로인지, 길이가 이상하지 않은지
     → 문제가 있는 문장만 다시 번역합니다. 끝까지 남은 문제는 보고서에 기록합니다.
3. **배치** (`layout.py`): 원문 글자만 지우고(배경·이미지·선은 유지) 그 자리에 한국어를 같은 크기, 색, 정렬, 줄 간격,
   들여쓰기로 씁니다. 번역문이 원래 영역보다 길면 **글자 크기를 지키는 방법부터** 차례로 시도합니다.
   띄어쓰기 단위 줄바꿈 → 글자 단위 줄바꿈 → 아래 빈 공간 사용(다른 문단·그림 바로 위까지) → 줄 간격 약간 축소 →
   (마지막 수단) 글자 크기 0.25pt씩 축소.
4. **배치 검증·수정** (`verify.py`, `pipeline.py`): 만들어진 PDF를 **다시 읽어서** 문단마다 원본과 비교합니다.
   비교 항목은 글자 크기, 첫 줄 가로·세로 위치, 줄 간격, 색, 영역 넘침, 다른 문단과 겹침, 빠진 글자, 지워지지 않은 원문입니다.
   차이가 있으면 원본에 맞게 설정을 고친 뒤(크기 복원, 위치 이동, 줄 간격 보정, 허용 영역 축소, 지우기 영역 확대) 다시 그리고 검증합니다.
   차이가 없어질 때까지 반복합니다. 번역문이 너무 길어 원래 크기로는 도저히 들어가지 않는 경우처럼 고칠 수 없는 차이는
   이유와 함께 보고서에 남깁니다.
5. **좌우 합치기**: 쪽마다 너비가 두 배인 페이지를 만들어 왼쪽에 원본, 오른쪽에 번역본을 놓습니다.
   PDF에는 실제로 쓴 글자만 담도록 글꼴을 줄여(subset) 저장합니다.

## 번역 엔진

- **claude** (기본값): Anthropic Claude API(`claude-opus-5-5`)를 쓰고, 문장 정렬을 지키도록 JSON 구조로 응답을 받습니다.
  `ANTHROPIC_API_KEY`가 필요하며 사용량만큼 요금이 나옵니다. 요청이 안전 정책에 걸려 거절되면 서버가 다른 모델로
  자동 재시도하도록(`fallbacks: "default"`) 설정해 두었습니다. `--model`로 다른 모델을 고를 수 있습니다.
- **google**: `deep-translator`로 무료 Google 번역을 사용합니다. 키가 없어도 되지만 비공식 경로라 많이 쓰면 막힐 수 있습니다.
- **dict**: 사람이 직접 번역하거나 다듬은 문장을 JSON으로 넣습니다. 보고서의 `translation` 값을 고쳐 다시 넣는 검수용으로도 쓸 수 있습니다.

새 엔진은 `Translator`를 상속해 `translate_paragraphs()`만 구현하면 됩니다.

## 테스트

```bash
python -m pytest
```

네트워크 없이 도는 가짜 번역기와 `examples/make_sample.py`로 만든 영어 PDF(제목, 소제목, 양쪽 정렬 본문, 색 상자, 2단, 그림)로 다음을 확인합니다.

- 문장 분리, 문단 인식(크기·굵기·정렬·색·2단)
- 문장/문단 검사가 오류를 잡고, 다시 번역해서 고치는지
- 번역본을 다시 읽었을 때 모든 문단의 글자 크기, 첫 줄 위치, 색이 원본과 같은지
- **일부러 크기·위치·줄 간격을 틀리게 그려도** 검증·수정 반복으로 원본과 같아지는지
- 번역문이 아주 길어도 다른 문단이나 그림과 겹치지 않는지, 크기를 줄였다면 보고서에 남는지
- 나눔고딕에 없는 글자 처리, 좌우 비교 PDF(왼쪽 영어 / 오른쪽 한국어)

## 한계

- 스캔한 이미지 PDF는 글자 정보가 없어서 OCR을 먼저 해야 합니다.
- 기울어지거나 세로로 쓴 글자, 표 안의 아주 작은 칸은 원본 그대로 둡니다.
- 한국어 글꼴은 나눔고딕 한 종류(보통/굵게)만 씁니다. 기울임(italic)은 따로 표현하지 않습니다.
- 문단 안에서 일부 단어만 굵거나 색이 다른 경우, 번역본에는 그 문단의 주된 스타일 하나로 그립니다.
